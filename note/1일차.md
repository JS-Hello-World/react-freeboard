## FSD 아키텍처

- 계층별로 기능별로 나누어 놓은 구조.
- 부모는 자식을 볼 수 있지만, 자식은 부모를 볼 수 없음.

```
src/
│
├── app/        # 앱 초기화 및 루트 설정 (라우터, 테마, 글로벌 상태 등)
├── processes/  # 비즈니스 흐름 (예: 로그인 프로세스, 장바구니 결제 프로세스)
├── pages/      # 라우팅 단위 페이지
├── widgets/    # 페이지를 구성하는 UI 블록 (컨테이너 개념)
├── features/   # 도메인 단위의 핵심 기능 (예: delete, likeButton 등)
├── entities/   # 순수 도메인 모델 (예: user, product 등, CRUD 중심)
├── shared/     # 공통 유틸, 컴포넌트, 스타일, lib 등
```

### normalize css

```bash
npm install normalize.css
```

| 항목 | `reset.css`                | `normalize.css`           |
| ---- | -------------------------- | ------------------------- |
| 목적 | 모든 기본 스타일을 제거    | 브라우저 차이만 보정      |
| 방식 | 전면 초기화 (margin: 0 등) | 유지할 건 유지하고 보정만 |
| 결과 | 스타일 작성 부담 증가      | 스타일 유지 + 호환성 ↑    |

### React Router

- 라우팅을 위한 라이브러리

```javascript
<BrowserRouter>
  <Routes>
    <Route path="/" element={<App />} />
    <Route path="/auth/signin" element={<SigninPage />} />
  </Routes>
</BrowserRouter>
```

### React Query

`useQuery`와 `useMutation`은 데이터 패칭 이후 작업에서 할 일들을 편하게 할 수 있게 여러가지 기능 제공

- `useQuery` : 조회(**GET**) 할 때 사용
- `useMutation` : 변경(**POST, PUT, DELETE**) 할 때 사용

- `queryClient.invalidateQueries`: **queryKey**의 key를 가진 캐시 무효화
